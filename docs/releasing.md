# ROS Release Plan

The public release has two ordered repositories:

1. Release Wirestead core as ROS package `wirestead`.
2. Release this repository after `wirestead` resolves through rosdep.

Expected Jazzy Debian packages:

```text
ros-jazzy-wirestead
ros-jazzy-wirestead-ros
```

`wirestead_msgs` and `wirestead_bridge` will be added only after their public
interfaces are implemented and tested.

## Current v0.9.4 phase

Core v0.9.4, released 2026-08-16, is the first tag to carry the ROS manifest;
v0.9.3 predates it and stays immutable. `wirestead_ros.repos` now resolves that
tag rather than core `main`, so a source workspace builds the same core the
Bloom release will describe.

CI deliberately stays on core `main`: pinning it too would trade away the
integration regressions it exists to catch before the next tagged release. The
two therefore answer different questions, and only the manifest needs to be
immutable. CI still skips the unresolved `wirestead` rosdep key, which is what
Bloom registration removes.

This phase still does not produce `ros-jazzy-wirestead` or
`ros-jazzy-wirestead-ros` apt packages. That needs the two release repositories
and the rosdistro pull requests below.

## Repository and package names

| Role | Name |
| --- | --- |
| Core source repository | `wirestead/wirestead` |
| Core ROS package | `wirestead` |
| Core release repository | `wirestead/wirestead-release` |
| Integration source repository | `wirestead/wirestead-ros` |
| Integration ROS package | `wirestead_ros` |
| Integration release repository | `wirestead/wirestead-ros-release` |
| rosdistro repository keys | `wirestead`, `wirestead_ros` |

Hyphens are appropriate for Git repository names. ROS package names use lower
case and underscore separators, so `wirestead_ros` follows REP-144. Debian
package names are generated by replacing underscores with hyphens.

## Before the first release

- Merge the core `package.xml` and verify the core appears as build type
  `ros.cmake` in `colcon list`.
- At the next naturally scheduled core release, bump the CMake project and
  `package.xml` to the same version and create a new core tag. Do not reuse
  `v0.9.3`, which predates the ROS manifest.
- Point `wirestead_ros.repos` at that immutable core tag.
- Verify clean Jazzy builds on Ubuntu 24.04.
- Add and review `CHANGELOG.rst` for each released ROS package.
- Verify package names remain available in the ROS Index.
- Create public, initially empty `wirestead-release` and
  `wirestead-ros-release` repositories.

## Ordered registration

Install the release tools and release the core repository first:

```bash
sudo apt install python3-bloom python3-catkin-pkg
bloom-release --new-track --rosdistro jazzy --track jazzy wirestead
```

Bloom creates the rosdistro pull request. After it is merged, confirm that the
core build farm jobs succeed and that `ros-jazzy-wirestead` reaches
`ros-testing`. Only then release this repository:

```bash
bloom-release --new-track --rosdistro jazzy --track jazzy wirestead_ros
```

After the generated rosdistro pull request is merged, monitor the ROS build
farm and test packages from `ros-testing` before the next distribution sync.

```bash
sudo apt install ros-jazzy-wirestead ros-jazzy-wirestead-ros
```

For later versions, update the changelog and package version, tag the source,
and run `bloom-release` again without `--new-track`.
